# 语义化灯控协议与 MCU 本地闪烁计划

## Summary
- 将串口 `0x21` 从“原始 RGB 帧透传”直接替换为“语义化灯控命令”。
- 外部只发送：目标灯、RGB、是否闪烁、闪烁翻转间隔；不再发送 `spi_bus`、`led_count`、整条 RGB buffer。
- MCU 本地维护 16 颗 LED 的颜色/闪烁状态，并由本地任务按时间间隔刷新 WS2812。
- 单灯控制只改变目标 LED，其他 LED 保持当前状态。

## Key Changes
- 保持现有串口帧外壳不变：`55 AA cmd len payload checksum`，响应仍为 1 字节 status：`0=OK`，`1=ERROR`。
- `cmd=0x21` 新 payload 固定 7 字节：
  - `target`: `0xFF` 表示全部 LED，`0x00..0x0F` 表示单颗 LED index。
  - `flags`: bit0=`blink_enable`，bits1-7 必须为 0。
  - `red, green, blue`: 各 0-255。
  - `interval_ms`: uint16 little-endian，表示亮/灭翻转间隔；`blink_enable=0` 时忽略，`blink_enable=1` 时必须 `>=20ms`。
- 固件端新增本地灯控状态：
  - 每颗 LED 保存 `rgb`、`blink_enable`、`interval_ms`、当前亮灭相位、下次翻转时间。
  - 新命令被接受后立即刷新一次输出；闪烁命令第一帧先显示亮态，然后由 MCU 定时翻转。
  - 非法 target、flags、interval 不改变当前灯态，并返回 ERROR。
- `WS2812Manager` 从“接收外部整帧 RGB”改为“拥有灯控语义和状态机”：
  - `Init(strip, spi_bus, led_count)`，其中 `led_count=16` 在 `app_main.cpp` 本地配置。
  - 新增 `SetLightControl(target, rgb, blink_enable, interval_ms)`。
  - 新增低优先级本地控制线程，建议 10ms tick，只在可见灯态变化时调用 `WS2812Strip::ShowRGB()`。
- `IMUUartBridgeTask` 只负责解析 `0x21` 的 7 字节参数并调用 manager，不再把串口 payload 读进 SPI TX buffer。
- Python 工具同步改协议：
  - `rgb R G B` 发送全部 LED 固定颜色。
  - `blink R G B --delay-ms N` 发送一次命令后退出，闪烁由 MCU 持续执行。
  - `led I R G B` 只设置单颗 LED。
  - 增加 `led-blink I R G B --delay-ms N`。
  - 移除灯控命令里的 `--spi-bus`、`--led-count` 依赖。

## Test Plan
- 构建验证：`cmake --preset Debug`，`cmake --build --preset Debug`。
- 协议验证：
  - `ping` 正常。
  - `rgb 135 206 250` 后全部 16 颗常亮。
  - `blink 135 206 250 --delay-ms 300` 只发送一次串口命令，脚本退出后 MCU 仍继续闪烁。
  - `led 3 255 0 0` 只改变第 3 颗，其他灯保持原状态。
  - `led-blink 3 255 0 0 --delay-ms 300` 只让第 3 颗闪烁。
  - `off` 使用 `target=0xFF, rgb=0,0,0, blink=0` 熄灭全部。
- 异常验证：
  - `target=16`、reserved flags 非 0、blink interval `<20ms` 返回 ERROR，原灯态不变。
  - IMU 主动推送仍保持，灯控闪烁不依赖上位机持续发帧。

## Assumptions
- 当前实际灯珠数按 16 颗实现。
- `interval_ms` 是翻转间隔：300ms 表示亮 300ms、灭 300ms。
- 旧 `0x21` 原始 RGB 帧不再兼容，旧上位机脚本必须同步更新。
- 不改 `WS2812Strip` 的底层编码方式，也不改当前 SPI TX buffer 大小。
